# How the fake registry data were made

**FAKE DATA: generated locally, with no patient rows sampled from a source workbook.**

Seed: `20261108`. Each file has 100 rows. Exact header names and order match the supplied lists.

## Generation choices

- IDs use separate SYN_REG_ENDO_, SYN_REG_MGH_ and SYN_REG_LEGACY_ namespaces. PRISM IDs use SYN_PRISM_. They do not link to real people or imply overlap between the three cohorts.
- Dates are invented from a 2020–2024 baseline period. The MGH Date of scope is generated 30–365 days after its index date. These are demo choices, not source date coverage or matching rules.
- Supplied category frequencies are used as illustrative sampling weights for described fields. At least one example of each supplied treatment/status category is retained where generated by the category helper. No source frequency table is reproduced by the 100 rows.
- Endoscopy examples use CD/UC labels. The toy generator puts HBI and SES-CD values on CD examples, SCCAI values on UC examples, and uses N/A for the disease-classification fields that it leaves inapplicable. These are generation choices, not a claim about the source missingness mechanism.
- SES-CD values are mostly zero among the generated nonmissing SES-CD values. Numeric scores stay within the observed example ranges supplied by Enci.
- The MGH 12-month response examples use the three supplied category names with arbitrary equal starting weights. Their frequencies and missingness do not describe the real 12-month data.
- Missing cells are invented for illustration. No original missing-value rates have been estimated.
- Unspecified fields stay blank. This includes modifiedbaronsscore, legacy sex/ethnicity/race coding, medication and lab values, wk30_remis, endo_date, crohns, the three composite fields and endo_remission.
- Literal N/A and other raw status strings are preserved. No status-to-remission recoding or clinical threshold is applied.
